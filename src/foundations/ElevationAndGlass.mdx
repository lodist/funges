# Elevation and glass

Elevation is a **role**, not a shadow value. Pick a level by what the surface
does — is it page background, input chrome, a dismissible overlay, a blocking
dialog — and the shadow follows. Picking by how deep the shadow looks is how a
scale drifts into a dozen one-off values.

## The levels

| Level           | What it is for                                                                                                                                     |
| --------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `base`          | The map canvas. Not a discrete surface — carries no shadow at all, which is why there is no `.elevation-base` class to apply.                      |
| `control`       | A small control you press: Button, the Slider thumb, Checkbox, Switch, a RadioGroup item.                                                          |
| `raised-subtle` | Lightweight input chrome you look through rather than press: the search field, a Select trigger, Textarea.                                         |
| `raised`        | Small static chrome: Card, the sidebar, the mobile navbar.                                                                                         |
| `floating`      | Overlays you dismiss by tapping outside: Sheet, Popover, DropdownMenu.                                                                             |
| `floating-up`   | `floating`, cast upward. Bottom Sheet only — pinned to the viewport's bottom edge, where a downward shadow falls off-screen and separates nothing. |
| `overlay`       | Blocking dialogs behind a scrim.                                                                                                                   |

Light and dark are one scale, not two: the offsets and blurs are identical and
only the alpha deepens. In dark mode a black drop shadow is nearly invisible,
so the real depth cue becomes a 1px inset highlight along the top edge.

### Interactive escalation

`elevation-interactive` is not a level — it is the modifier that makes one
move, escalating on hover and settling back on press. Pair it with a level:
`elevation-control elevation-interactive` for a Button,
`elevation-raised elevation-interactive` for a Card. The level decides how far
the surface lifts, by publishing `--elevation-rest` and `--elevation-lift`;
the modifier only animates between them. On its own it animates nothing.

`raised-subtle` publishes neither on purpose — input chrome does not escalate.
This is the only sanctioned way to animate elevation; hand-rolling a hover
shadow puts a value outside the scale.

## Glass

Glass is **opt-in per component** and answers to two hard rules:

1. **Only on `raised` or `floating` chrome.** Never on `base` — the map canvas
   is not a surface — and never on `overlay`, because a blocking dialog must
   stay opaque to hold contrast over a busy map.
2. **Small, fixed-size chrome only.** A full-bleed translucent panel over the
   map cannot guarantee contrast against whatever happens to be underneath it.

Both variants degrade to an opaque background when `backdrop-filter` is
unsupported, or when the viewer asks for reduced transparency or increased
contrast. That fallback is not a nicety — it is what keeps the text readable.

### glass-regular

The default. Roughly nine-tenths opaque, so body copy on it stays legible.

<Story of={ElevationStories.GlassRegular} />

### glass-clear

Markedly more transparent, and reserved for **full-bleed media** — an image or
map tile showing through. Do not put text-heavy or contrast-critical content on
it; there is no contrast guarantee, because there is no telling what is behind.
